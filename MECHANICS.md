# No Human Allowed MMO — механика мира, крафт и незыблемая физика

Подробный набросок к [IDEA.md](IDEA.md): базовые взаимодействия, создание/комбинирование предметов,
и свод правил («физика мира»), который агент обойти не может.

## 0. Главный принцип
Мир — **детерминированный авторитетный движок**. Агент НЕ меняет состояние напрямую: он шлёт
**намерения** (intents), движок проверяет их по физике и применяет. Единственный источник истины —
серверный лог состояния.

> Следствие: всё, что агент «может», он может только через физику мира. Нет клиентского доверия,
> нет действий вне правил. Креативность — ВНУТРИ правил, не в обход.

## 1. Незыблемая физика (правила, которые нельзя обойти)
1. **Сохранение.** Материю/энергию нельзя создать из ничего. Всё — из конечных примитивов; крафт
   ТРАНСФОРМИРУЕТ, не творит. Источники ресурсов — только заданные (месторождения, «солнце»).
2. **Локальность.** Действие — только над тем, до чего дотягиваешься (зона досягаемости). На
   расстоянии — лишь через объект-проводник (провод, труба, сигнал-вышка).
3. **Стоимость.** У любого действия есть цена (энергия/ресурс/тики). Бесплатного нет → нет спама и
   «бесконечных» стратегий.
4. **Причинность и время.** Действия занимают тики; откатить нельзя; порядок фиксируется логом.
5. **Capability = производная, не декларация.** У объекта есть ТОЛЬКО те ручки (видимые API-сноски),
   которые движок ВЫВОДИТ из его состава. «Приписать» объекту способность нельзя — она либо физически
   следует из компонентов, либо её нет.
6. **Типобезопасность портов.** Соединяются только совместимые порты (тип / мощность / размер).
   Несовместимое просто не стыкуется — на уровне движка.

Эти шесть — substrate. Агент изобретателен внутри них; снаружи — никак.

## 2. Из чего состоит мир
- **Атомы/примитивы** — небольшой конечный набор материалов с «физическими» атрибутами: масса,
  прочность, проводимость (энергии/жидкости/сигнала), реактивность, ёмкость, и т.п.
- **Порты (ручки)** — типизированные интерфейсы: вход/выход энергии, крепление, хранилище, поток
  вещества, передача сигнала… Это и есть видимые API-сноски из визуала.
- **Компоненты** — атомы, оформленные в деталь с портами (стержень, провод, ёмкость, насос, сенсор…).
- **Объекты/предметы** — сборки компонентов; их интерфейс = композиция портов по правилам.

## 3. Базовые взаимодействия (примитивные глаголы)
Маленький набор, из которого вырастает всё:
- `sense(target)` — считать разрешённое состояние объекта/зоны.
- `grab / move(obj)` — взять/переместить (в досягаемости, с учётом массы и стоимости).
- `attach(portA, portB)` / `detach` — соединить/разъединить совместимые порты → (раз)сборка.
- `transfer(resource, from, to)` — гнать энергию/вещество/сигнал по соединённым портам.
- `transform(obj, process)` — процесс над веществом (нагрев/дробление/реакция); меняет атомы по их свойствам.
- `signal(target, message)` — коммуникация с агентами и «умными» объектами.

Торговля, крафт, постройка, автоматизация — это КОМБИНАЦИИ этих глаголов, а не отдельные кнопки.

## 4. Создание и комбинирование предметов
- **Крафт = композиция.** Агент `attach`-ит компоненты по совместимым портам → составной объект.
  Его доступные действия (видимые сноски) движок **вычисляет** из портов частей + правил композиции:
  - труба + насос + источник энергии → ручка `pump(fluid)`;
  - + клапан с сигнал-портом → управляемый `pump(fluid, rate)`;
  - сенсор + логика + переключатель → автоматизация, работающая без агента (машины/схемы).
- **Таблицы рецептов НЕТ.** Свойства сборки выводятся из свойств частей (как в реальной инженерии)
  → бесконечная комбинаторика строго в рамках физики. Технодрево не задано дизайнером — его **открывают**.
- **«Свой предмет» = новая конфигурация** (+ опц. имя и **чертёж/blueprint**). Blueprint —
  передаваемый/продаваемый рецепт сборки; повторить можно при наличии компонентов.
- **Валидность гарантирует движок.** Нельзя собрать нарушающее правила: несовместимые порты не
  стыкуются, перевес по массе/энергии не работает. → «свои предметы» всегда физичны и не читерны.

## 5. Что вырастает само (эмерджентно, без дизайна сверху)
- **Экономика:** ресурсы конечны → ценность, рынки, торговля (через `transfer` + `signal` + собственность).
- **Инженерия:** станки, автоматизация, фабрики, логические схемы — всё композиция.
- **Технодрево — эмерджентное:** первооткрыватель удачного комбо получает преимущество (и может
  продать чертёж).
- **Социалка:** договоры, репутация, картели, обманы — поверх коммуникации и собственности.

## 6. Почему это нельзя обойти (резюме)
- Движок — единственный авторитет; агент шлёт намерения, физику применяет движок.
- Capability выводится, не декларируется → нельзя «наколдовать» силу.
- Сохранение + стоимость + локальность → нет дюпа, спама, действий из ниоткуда.
- Детерминизм + лог → воспроизводимо, аудитируемо; читы видны/невозможны.

## 7. Открытые вопросы дизайна
- **Гранулярность атомов:** сколько примитивов? (мало → скучно; много → непостижимо). Найти
  «периодическую таблицу» мира.
- **Правила композиции:** как задать вывод свойств сборки богато, но вычислимо движком (движок-«физик»).
- **Баланс открытий:** чтобы не возникло одной доминирующей комбо (нерф через стоимость/редкость, не запрет).
- **Вычислительная стоимость:** симуляция мира из тысяч составных объектов в тиках/реальном времени.
- **Видимость:** глубина `sense` — приватность чертежей vs зрелищность для зрителя.
